# Enchat Bridge — первый официальный бот TAGa-Say

Мост между TAGa-Say и публичными комнатами [Enchat](https://github.com/sudodevdante/enchat).
Пользователь добавляет бота в чат и командует `/connect <комната>`, после чего сообщения
ретранслируются в обе стороны.

> **Важно:** Enchat — отдельный проект © sudodevdante с ограничительной лицензией
> (internal use only; запрет redistribution / modification / decompilation без письменного
> согласия). Мы **не включаем код Enchat** в TAGa-Say и не распространяем его.
> Мост — независимый opt-in коннектор, который запускается пользователем отдельно и
> взаимодействует с Enchat по сети. Перед публикацией/коммерческим использованием
> требуется письменное разрешение правообладателя Enchat.

## 1. Что такое Enchat (по исходникам и README)

- Терминальный E2EE-чат на Python, транспорт — [ntfy](https://ntfy.sh) (self-hosted или
  `https://enchat.salvc.com`).
- Комната = ntfy-топик; у публичной комнаты случайный топик `enchat-public-…`.
- Секрет комнаты — 32 случайных байта в base64url; ключ шифрования:
  `Fernet(PBKDF2-HMAC-SHA256(secret, salt=SHA256(topic), 480_000, 32))`.
- Сообщение: `MSG:<fernet>`, системное: `SYS:<fernet>`, внутри plaintext
  `V2|<unix_ts>|<nick>|<content>`. Есть файлы: `FILEMETA:` / `FILECHUNK:`.
- Публичный каталог: ntfy-топик `enchat-public-directory-v2-…`, записи `ROOM2:<fernet>`
  с `{v,id,name,topic,secret,lease}`; лиз 105 с, обновление каждые 75 с.
- Приглашения: `https://share.enchat.io/join#<session>:<key>`; сервер видит только
  зашифрованный blob, ключ в fragment.
- Tor: SOCKS5 127.0.0.1:9050.
- Ограничения: у комнаты один статический ключ (нет ratchet/PFS), нет подписей личности,
  relay видит IP/время/размер/топик; публичные комнаты не дают membership secrecy;
  внешнего аудита не было.

## 2. Архитектура моста

```
TAGa-Say chat ──E2EE──► TAGa-Say relay ──plaintext──► Bot Gateway
                                                          │
                                                   enchat-bridge
                                                          │
                                        ntfy HTTP/JSON (TLS / Tor)
                                                          │
                                                   Enchat room
```

- Мост — **доверенная конечная точка**: он расшифровывает сообщения TAGa-Say (потому что
  бот получает их в plaintext) и шифрует их ключом комнаты Enchat. Сквозного шифрования
  *через* мост нет — это надо явно показывать пользователю.
- Состояние — только в памяти: `chat_id ↔ room(topic, secret, nick)`, последний event id,
  LRU dedupe. На диск ничего не пишется; логи без текста.
- Один процесс обслуживает N чатов; лимит 1 мост на чат, 10 комнат на бота.

## 3. Команды бота

| Команда | Действие |
|---|---|
| `/start` | краткая справка и предупреждение о мосте |
| `/connect <name\|topic> [--nick N]` | подключить чат к публичной комнате |
| `/connect-link <url>` | подключить по invite-ссылке Enchat |
| `/disconnect` | отключить мост |
| `/rooms` | список активных публичных комнат |
| `/status` | комната, relay, задержка, счётчики |
| `/nick <name>` | сменить ник в Enchat |
| `/bridge on\|off` | пауза/возобновление ретрансляции |
| `/security` | напоминание: мост видит plaintext |

Публичный каталог: мост получает `ENCHAT_DIRECTORY_TOPIC` и `ENCHAT_DIRECTORY_KEY` из
конфигурации (не хардкодим чужие константы в репозитории). Если их нет — доступны только
явные `/connect` по topic+secret или invite-ссылке.

## 4. Формат ретрансляции

TAGa-Say → Enchat (≤ 500 символов, как `MAX_MSG_LEN`):

```
[TAGa-Say] Lilanga: привет
```

Enchat → TAGa-Say:

```
[Enchat] nick: привет
```

Правила:
- свои сообщения не отражаем (сравнение по event id и по нику + тексту в окне 5 с);
- HTML/Markdown Enchat не поддерживает — экранируем, обрезаем, убираем переводы строк;
- упоминания `@nick` сохраняем;
- файлы Enchat ≤ 5 МиБ: мост скачивает, проверяет антивирусом TAGa-Say и отправляет как
  обычное вложение; обратно — только файлы ≤ 5 МиБ;
- rate limit: 5 сообщений / 2 с в комнату, очередь с backoff при 429/5xx.

## 5. Безопасность

- Бот работает с scope `messages:read` + `messages:send` только в чатах, куда его добавили.
- Токен бота — в secret manager, не в образе; ротация.
- Egress allowlist: только `ENCHAT_RELAY` (и Tor SOCKS при включении).
- Никаких URL из сообщений не запрашиваем (SSRF).
- Валидация: topic `[A-Za-z0-9_-]{1,64}`, secret 43–44 base64url, nick ≤ 40, текст ≤ 500.
- При старте — предупреждение в чате: «Мост Enchat видит сообщения в открытом виде».
- Метрики: количество ретранслированных сообщений, ошибки, задержка; без содержимого.
- Kill switch: `/bridge off` и глобальный флаг.

## 7. Почему не встроить Enchat в APK

- Лицензия запрещает redistribution/modification.
- Python-рантайм + Tor увеличивают размер и поверхность атаки.
- Мост — отдельный сервис, его можно не включать в сборку и отключить на сервере.
