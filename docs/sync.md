# Синхронизация состояния

Состояние пользователя хранится на relay в зашифрованном виде. Сервер не видит
ни профиль, ни папки, ни историю звонков.

## API

- `GET /v1/state` (Bearer access token) → `{version, ciphertext, updatedAt}`.
- `PUT /v1/state` → `{ciphertext, updatedAt}`; версия увеличивается сервером.
- `POST /v1/profile` → `{displayName, bio}`; обновляет публичный профиль
  в directory (имя, «О себе»).

Лимит ciphertext — 2 МиБ. Без токена — `401`.

## Ключ

```
master   = random 32 bytes, хранится только на устройстве
           (обёрнут ключом Android Keystore, не уходит на сервер)
key      = HKDF-SHA256(ikm = master, salt = username, info = "taga/state/v2")
AAD      = "taga/state/v2|" + username
```

Verifier пароля **не используется** для шифрования состояния: сервер знает
verifier и не должен иметь возможности расшифровать профиль, контакты,
журнал звонков и истории. Старый формат v1 (ключ из verifier) считается
скомпрометированным: при первом запуске он расшифровывается один раз,
перешифровывается в v2 и перезаписывается на сервере.

Минус текущей схемы: без привязки нового устройства master-ключ не
восстанавливается после полного удаления приложения. Восстановление и
мультиустройство — этап 5 (`docs/roadmap`).

## Что синхронизируется

- профиль (имя, username, телефон, bio, цвет аватара);
- настройки: тема, обои, размер текста, углы, приватность, уведомления;
- папки чатов;
- стикер-паки и избранное;
- журнал звонков;
- контакты и каналы;
- истории (метаданные и зашифрованные медиа).

Личные сообщения синхронизируются отдельно через mailbox конвертов; история
переписки на новом устройстве пока не восстанавливается.

## Медиа историй

`StoryTransfer` шифрует изображение AES-256-GCM, загружает ciphertext в
`/v1/media`, а `mediaId` и ключ кладёт в состояние. Другое устройство
скачивает блоб, проверяет SHA-256 и расшифровывает в `filesDir/stories`.
AAD: `taga/story/v1|<sha256>|<mime>`.

## Частота

`SyncManager` делает pull при старте, затем push каждые ~15 секунд, если
локальный хеш состояния изменился. Конфликты решаются по версии сервера:
перед push клиент принимает более новую версию, затем отправляет merged state.
